* C and C++ ABI

Solvers live in Rust. Geometry hosts that call one outer iteration at
a time hold an opaque ~xts_solver_t~; scripts that want a one-shot
solve still call ~xts_minimize~. Every vector is a dlpk
~DLManagedTensorVersioned~ tensor.

** Session (eOn / ASE ~step~)

#+begin_src c
#include "xts.h"

xts_control_t ctrl = { .maxiter = 200, .gtol = 1e-8, .istep = 1.0, .memory = 8 };
xts_solver_t *s = xts_solver_create(XTS_LBFGS, &ctrl, n);
xts_report_t report;
while (!done) {
    xts_solver_set_maxmove(s, max_move);
    xts_solver_step(s, eval, grad, user, x, &report);
}
xts_solver_free(s);
#+end_src

~xts_solver_forget~ drops pairs / conjugacy / moments. Newton and RFO
use ~xts_solver_step_hess~. Callbacks are arguments of each step, not
stored on the handle.

** One-shot

#+begin_src c
#include "xts.h"

xts_control_t ctrl = { .maxiter = 200, .gtol = 1e-8, .istep = 1.0, .memory = 8 };
xts_report_t report;
xts_status_t st = xts_minimize(eval, grad, user, x, &ctrl, XTS_LBFGS, &report);
#+end_src

A non-CPU tensor returns ~XTS_UNSUPPORTED_DEVICE~. The ABI does not
change when a CUDA path lands.

** C++

#+begin_src cpp
#include <xts/optimize.hpp>

xts::optimize::Control ctrl;
auto report = xts::optimize::minimize(eval, grad, user, x, ctrl,
                                      xts::optimize::Method::Lbfgs);
#+end_src

xtensor callers include ~xts/xtensor.hpp~, which adapts ~xt::xarray~ to
the same ~xts_minimize~ entry. There is no solver in the header.
